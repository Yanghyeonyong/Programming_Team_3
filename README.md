# PaperFunk

PaperPunk는 Unity 기반 액션 게임 프로토타입입니다. 플레이어는 스테이지를 진행하며 적을 처치하고 보스를 상대하며 다음 스테이지로 이동하는 구조로 설계되어 있습니다. 현재 프로젝트는 타이틀/크레딧 UI, 스테이지 관리, 적 풀링, 플레이어 입력/전투, 보스 패턴에 집중되어 있습니다.

## 기술 스택

- Unity 2022.3.61f1
- TextMeshPro 3.0.7
- 커스텀 입력 처리 (`Input.GetAxisRaw`, 마우스 클릭)
- 오브젝트 풀링 기반 적/투사체 재사용

## 핵심 기술 소개

### 1. 타이틀과 UI 흐름

- `TitleUIManager.cs` : 타이틀 씬의 게임 시작, 설정/컨트롤 패널 열기·닫기, 씬 전환을 제어합니다.
- `CreditManager.cs` : 크레딧 스크롤, 자동 타이틀 복귀, 스킵 버튼을 처리합니다.

### 2. 스테이지 및 게임 상태 관리

- `GameStateManager.cs` : 싱글턴으로 스테이지 번호, 플레이어 타입, 적 수, BGM 재생, 다음 스테이지 인식, 게임 재시작/플레이어 사망 이벤트를 관리합니다.
- `EnemySpawner.cs` : 스테이지별 최대 적 수, 스폰 지점, 적 사망 시 재생성, 엘리트 적 소환 로직을 처리합니다.
- `EnemyPool.cs` : 일반 적과 엘리트 적을 큐 기반 풀링으로 재사용하여 생성 비용을 낮춥니다.

### 3. 플레이어 입력, 이동, 전투

- `InputComponent.cs` : `Horizontal`, `Vertical`, 마우스 버튼 입력을 캡처하여 다른 컴포넌트에 전달합니다.
- `MoveComponent.cs` : 입력 기반 이동, 회전, 플립/대시 스타일 동작, 애니메이터 연계를 담당합니다.
- `Player.cs` : 체력, 근접 공격, 원거리 파이어볼 발사, 피격 반응, 다음 스테이지 인식 충돌 처리를 구현합니다.
- `Spell.cs` : 스킬 애니메이션을 재생하고 완료 시 오브젝트를 비활성화합니다.

### 4. 적과 보스 패턴

- `Enemy.cs` : 체력, 공격/스펠 딜레이, 추적, 장애물 감지, 스턴, 오디오 재생을 포함한 기본 적 행동을 제공합니다.
- `BossEnemy.cs` : 소환, 충전형 스킬, 파이어볼, 플레이어 거리 감지 기반 전투 패턴을 확장합니다.
- `BossSecondSpell.cs`, `EnemyRange.cs`, `MapPattern.cs`, `MapPatternTrigger.cs` : 보스 및 맵 패턴 연출을 지원하는 보조 컴포넌트입니다.

### 5. 런타임 최적화와 재사용

- `EnemyPool.cs` : 적과 엘리트 적을 미리 생성해 활성화/비활성화 방식으로 재사용합니다.
- `Player.cs` : 파이어볼 오브젝트 풀링을 통해 반복 생성 비용을 낮춥니다.
- `Spell.cs`, `BossSecondSpell.cs` : 애니메이션 기반 스킬 오브젝트를 재사용하여 런타임 비용을 줄입니다.

### 6. 연출과 애니메이션 기반 동작

- 애니메이터 트리거와 코루틴을 조합해 공격 타이밍과 스킬 발동을 제어합니다.
- `Spell.cs`는 애니메이션 길이에 맞춰 스킬 실행을 완료한 뒤 오브젝트를 비활성화합니다.
- `BossEnemy.cs`는 충전, 소환, 원거리 공격 등 복합 패턴을 애니메이션 기반으로 구현합니다.

## 기술 결정 기록

이 섹션은 이 프로젝트가 어떤 이유로 현재 구조를 선택했는지를 정리한 것입니다.

### ADR-001. Unity LTS + 기본 모듈 기반 구현

- 배경 : 안정적인 개발 환경과 편리한 디버깅을 위해 LTS 버전 사용이 필요했습니다.
- 결정 : `2022.3.61f1` 기반으로 빌드하고, 외부 네트워크/인증 라이브러리 없이 로컬 액션 프로토타입 구현에 집중했습니다.
- 채택 이유 : 에디터 안정성과 패키지 호환성을 우선해 빠른 반복 개발이 가능했습니다.

### ADR-002. 입력/이동/전투 컴포넌트 분리

- 배경 : 플레이어 입력과 이동, 전투 로직을 한 클래스에 몰아넣으면 유지보수가 어려웠습니다.
- 결정 : `InputComponent`, `MoveComponent`, `Player`로 역할을 분리했습니다.
- 채택 이유 : 각 컴포넌트가 단일 책임을 갖도록 하여 확장성과 디버깅 효율성을 높였습니다.

### ADR-003. 오브젝트 풀링으로 적 재사용

- 배경 : 스테이지별 적 생성/제거가 과도하면 프레임 드랍 위험이 있었습니다.
- 결정 : `EnemyPool`을 도입해 일반 적과 엘리트 적을 큐 기반으로 재사용했습니다.
- 채택 이유 : 다수 적이 등장하는 스테이지에서 GC와 생성 비용을 줄이기 위해 적합했습니다.

### ADR-004. 보스 패턴과 일반 적 분리

- 배경 : 보스 전투는 일반 적과 다른 상태와 스킬 흐름이 필요했습니다.
- 결정 : `BossEnemy`를 `Enemy`에서 확장하여 소환/충전/원거리 스킬을 별도 로직으로 관리했습니다.
- 채택 이유 : 보스 특화 동작을 분리하면 밸런스 조정과 테스트가 더 수월합니다.

## 핵심 흐름

- 타이틀 : `TitleUIManager.cs`가 타이틀 씬에서 시작과 설정/컨트롤 UI를 관리합니다.
- 게임 시작 : `GameStateManager.cs`가 플레이어 프리팹을 인스턴스화하고 BGM, 스테이지 데이터를 초기화합니다.
- 적 소환 : `EnemySpawner.cs`가 스테이지별 적 수를 확인하고, `EnemyPool.cs`에서 적을 꺼내 스폰합니다.
- 플레이어 전투 : `InputComponent.cs`가 이동/공격 입력을 캡처하고, `MoveComponent.cs`와 `Player.cs`가 이동과 공격 애니메이션을 실행합니다.
- 보스 전투 : `BossEnemy.cs`가 소환/충전/원거리 공격 패턴을 기반으로 보스 전투를 구성합니다.
- 다음 스테이지 : `Player.cs`의 다음 스테이지 인식 플레인 충돌로 `GameStateManager.cs`가 스테이지를 증가시키고 새 스테이지를 로드합니다.
